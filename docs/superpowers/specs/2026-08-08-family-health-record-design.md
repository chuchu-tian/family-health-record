# 家庭病例档案（Family Health Record）设计文档

日期：2026-08-08
状态：已与用户逐节确认通过

## 1. 项目概述

一个供一家四口使用的家庭病例档案 PWA 应用。每位家庭成员记录自己的病历：什么时间生了什么病、病情描述（起因、忌口、预防注意）、医生诊断、就诊信息、用药，并可上传影像资料和病历截图/PDF。上传的附件由 AI 自动识别为结构化文本与指标数值，经人工核对后保存，支持全局搜索与长期指标趋势。

**用户与设备**：
- Chuchu（管理员）：iPhone / Mac
- 男朋友：安卓手机 / Mac
- 父母：安卓手机 / Windows 电脑

**核心约束**：
- 适老化设计（大字号、大按钮、极简必填项），父母需能独立完成最基本的记录操作
- 病历为敏感隐私数据，必须登录后才能访问，任何密钥不进前端代码和 git
- 起步零固定成本（免费额度），唯一持续开销为 AI 识别按量费用（每张图约几分钱人民币）

## 2. 关键决策记录

| 决策点 | 结论 | 备选与理由 |
|---|---|---|
| 使用模式 | 每位成员自己记录自己的 | 而非一人代记 |
| 平台 | PWA（添加到主屏幕） | 微信小程序医疗类目个人无资质；原生 App 成本高。PWA 全设备通用、无审核，买房地图已验证家人可用 |
| 数据存放 | 云端 + 登录保护 | 匿名读写方案（买房地图模式）对病历不可接受；自托管无常开设备 |
| 登录方式 | 每人独立账号（邮箱+密码） | 用户明确选择，而非家庭共享密码 |
| 账号创建 | 管理员统一创建，无开放注册 | 注册环节封闭，防止外人进入 |
| 查看权限 | 全家互相可见 | 家庭档案的意义所在 |
| 编辑权限 | 本人可编辑自己的；管理员可编辑所有人的 | 用户明确选择。爸妈误触改不坏他人数据；管理员帮全家补充细节 |
| 记录字段 | 时间、病名、病情描述（起因/忌口/预防/备注）、诊断、就诊信息（医院/科室/医生）、用药 | 费用、复诊提醒不做（YAGNI）；指标数值随 AI 识别积累 |
| 附件类型 | 图片为主 + PDF | 无视频需求 |
| AI 识别 | 接入 Claude API（京东云网关），提取摘要+指标，人工核对后入库 | 用户接受按量费用；准确率不足 100% 故必须核对 |
| 提取用途 | 阅读 + 搜索 + 指标趋势（趋势为 M3） | 用户选了最全的 C |
| 主界面 | 成员门户式（四张成员大卡片） | 优于动态流式/混合式，长辈心智模型最简单 |
| 视觉风格 | 清爽药房绿（白底+草本绿） | 优于奶油手账风/医疗蓝 |
| 新增按钮文案 | 「＋ 新增」 | 用户指定（原稿「记一笔」弃用） |
| 技术路线 | Supabase 全家桶 + GitHub Pages 静态前端 | 优于 Vercel 全栈（无账号、国内访问不稳、复杂度高）和自建服务器（固定费用+运维负担） |

## 3. 系统架构

```
全家设备（iPhone/安卓/Mac/Win 浏览器 或 PWA 主屏幕图标）
    ↓ HTTPS
前端 PWA — GitHub Pages 托管
  纯 HTML/CSS/JS，无框架；代码公开但不含任何密钥
    ↓ Supabase JS 客户端（登录后才可访问）
Supabase（东京节点，国内连通性已由买房地图项目验证）
  ├─ Auth        邮箱+密码登录；4 个账号由管理员在后台创建
  ├─ Postgres    病历/用药/附件/指标数据；RLS 行级安全
  ├─ Storage     私有存储桶存照片与 PDF；未登录拿不到文件
  └─ Edge Function  AI 识别中转；持有 Claude 网关 token
    ↓ 仅 Edge Function 可调用
Claude API（京东云 Anthropic 兼容网关 modelservice.jdcloud.com）
  读化验单照片/PDF → 返回结构化摘要与指标 → 用户核对后入库
```

**两道安全边界**：
1. 未登录状态下，数据库、存储、Edge Function 全部拒绝访问（RLS + 私有桶 + 函数内校验 JWT）。
2. AI 网关 token 仅存于 Edge Function 环境变量（Supabase Secrets）。前端代码、git 仓库、浏览器网络请求中永远不出现该 token。

**费用**：Supabase 免费档（数据库 500MB / 存储 1GB / Edge Function 50 万次每月）+ GitHub Pages 免费 + AI 按量（家庭频率下每月几元人民币量级）。

## 4. 数据模型

五张核心表，均启用 RLS。

### members 成员表
| 字段 | 说明 |
|---|---|
| id | 主键 |
| auth_user_id | 关联 Supabase Auth 账号（一对一） |
| display_name | 称呼，如「爸爸」 |
| avatar | 头像 emoji |
| birth_year | 出生年份，可空 |
| role | `admin` / `member` |

### records 病历记录表
| 字段 | 说明 |
|---|---|
| id | 主键 |
| member_id | 归属成员 |
| occurred_on | 发病/就诊日期（必填） |
| illness_name | 病名（必填），如「高血压」 |
| cause | 起因/诱因，可空 |
| dietary_restrictions | 忌口，可空 |
| prevention | 预防注意，可空 |
| notes | 其他备注，可空 |
| diagnosis | 医生诊断结论，可空 |
| hospital / department / doctor_name | 就诊信息，均可空（自行用药时为空） |
| status | `ongoing` 进行中 / `recovered` 已痊愈 / `chronic` 长期慢性 |
| created_by / created_at / updated_by / updated_at | 审计字段，自动记录（含管理员代改） |

### medications 用药表（多对一挂在 records 下）
`record_id` 关联病历 + 药名、用法用量（如「每日一次，每次一片」）、备注。

### attachments 附件表（多对一挂在 records 下）
| 字段 | 说明 |
|---|---|
| record_id | 关联病历 |
| storage_path | Storage 私有文件路径 |
| file_type | `image` / `pdf` |
| ai_summary | AI 提取、经人工核对后的文字摘要，可空；纳入搜索 |
| uploaded_at | 上传时间 |

### metrics 指标数值表（支撑 M3 趋势图，M2 起即开始积累）
| 字段 | 说明 |
|---|---|
| member_id | 归属成员 |
| metric_name | 指标名（收缩压/舒张压/血糖/总胆固醇…） |
| value / unit | 数值与单位 |
| measured_on | 测量日期 |
| source_attachment_id | 来源附件，可空（空=手动录入） |

### RLS 权限规则（所有表统一）
- **读**：任何已登录家庭成员可读全部数据。
- **写（增/改/删）**：仅记录归属者本人，或 `role = 'admin'` 的成员。
- Storage 桶为私有；文件路径按 `member_id/` 前缀组织，读需登录，写同上述规则。

### 搜索
病名、诊断、各描述栏、用药名、AI 摘要纳入全文搜索（Postgres `ilike`/全文索引，M2 实现）。搜「血糖」命中全家所有相关记录。

## 5. 页面与交互

### 页面清单
1. **登录页**——邮箱+密码；登录态长期保持（爸妈一次设置基本永久免登录）。
2. **成员门户首页**——四张成员大卡片（头像+称呼+最近一条记录摘要），全局搜索框（M2 上线，M1 不显示），「＋ 新增」大按钮。点卡片进入该成员时间线。
3. **成员时间线页**——该成员病历按时间倒序的卡片列表（病名、日期、医院、用药/附件标签、状态标签）。
4. **病历详情页**——分块展示：医生诊断 / 用药 / 忌口与预防 / 附件缩略图。附件点开看原图与 AI 摘要。「编辑」按钮仅本人或管理员可见。
5. **新增/编辑页**——必填仅两项：病名 + 日期（默认今天）。拍照/上传、就诊信息、诊断、用药、忌口等全部折叠于「展开更多」。爸妈最短路径：新增 → 输病名 → 拍照 → 保存。
6. **AI 识别核对页**（M2）——上传后自动识别，展示可编辑的摘要与指标（异常值标 ⚠️），「确认保存」后才入库；可选「不保存摘要」只存原图。
7. **指标趋势页**（M3）——成员页「健康指标」标签，选指标看时间曲线，正常范围底色，异常点高亮。

### 适老化要求
- 正文字号 ≥ 18px，标题与按钮更大；触控目标 ≥ 48px
- 高对比度文字（药房绿风格下深绿/近黑文字于白底）
- 极简必填项；操作路径最短化；关键按钮全屏宽
- 无悬停依赖（全触屏可用）；错误提示用平实中文

### 视觉风格：清爽药房绿
白底 + 草本绿主色（#3a7d5c 一档），卡片圆角+轻阴影+左侧彩色描边，标签用浅绿底深绿字。整体像亮堂的社区药房：干净、安心、医疗感适中。

## 6. 错误处理

| 场景 | 策略 |
|---|---|
| 网络差/断网 | 保存失败明确提示并**保留表单内容**；PWA 缓存应用外壳可离线打开，数据读写需网络（第一版不做离线同步） |
| AI 识别失败/超时 | 提示「没认出来，可重拍或直接保存原图」；Edge Function 60 秒超时；AI 失败不阻塞存图 |
| 大文件上传 | 图片前端压缩至长边 2000px（约 1-2MB）再上传；PDF 不压缩，单文件限 20MB |
| 误删 | 删除需二次确认（提示附件一并删除）；不做回收站（YAGNI），靠确认+权限兜底 |
| 忘记密码 | Supabase 邮件重置为兜底；现实路径为管理员在后台手动重置 |
| 存储额度 | 1GB 约可存 600+ 张压缩图，够两三年；Supabase 到 80% 邮件提醒，届时再决策 |

## 7. 里程碑与验收

### M1 · 核心记录功能
登录、成员门户首页、病历增删改查（含用药/就诊信息/描述栏）、附件上传查看（含压缩）、成员/管理员权限、药房绿 UI、适老化、PWA、部署上线。

**验收**：四台真机（iPhone、两台安卓、Win）均能登录、新增带照片病历、互相查看；父母能独立完成「新增 → 病名 → 拍照 → 保存」。

### M2 · AI 识别 + 搜索
Edge Function 接京东云 Claude 网关、上传自动识别、核对页、摘要与指标入库、全局搜索。

**验收**：真实化验单照片经识别-核对-保存全流程；搜「血糖」命中对应记录。

### M3 · 指标趋势图
指标标签页、时间曲线、正常范围标注、异常高亮。

**验收**：多次血压数据可见趋势曲线。

## 8. 测试策略

- **RLS 权限**：SQL 测试脚本逐条验证读/写/改边界（含管理员）——隐私底线，必须自动化。
- **Edge Function**：单元测试模拟 AI 响应，覆盖解析成功/失败/超时兜底。
- **前端**：每里程碑末真机人工验收清单（照买房地图模式逐项验证）。
- **上线前安全自查**：未登录直接访问数据库 REST 接口与 Storage 文件 URL，必须全部拒绝。

## 10. 明确不做（YAGNI）

- 费用/医保记录、复诊提醒、回收站、离线编辑同步、消息推送、开放注册、视频附件、多家庭/多租户。
